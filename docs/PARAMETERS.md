# FLEXTH parameters


| Parameter Name	                  |    Default Value  |Values / Indicative range   |  Units	 |     Description  |	Note |
| -----------------                   |     -----------   |           -----            |  -----  |        -----     |  ----- |
|`param_tiling`                       |   False           | True, False                |  -      | If `True`, FLEXTH runs in sequence across tiled input rasters																																				  |  Useful for very large rasters and/or high resolutions and/or limited computational resources (especially memory)																																																																									     																	    |
|`param_tile_inputs`                  |   True            | True, False                |  -      | If `True`, the inputs are tiled (relevant only if `param_tiling = True`)                                                                                                                                     |  If `param_tiling=True`  then `param_tile_inputs` has to be set `True` in the first run. Once the inputs are tiled, it can be set to `False`                                                                                                                                                                                                                                                                              																		|
|`param_tile_size`                    |   10000           | [100,1000000]              |  -      | Length in pixel of the edge of the squared tiles                                                                                                                                                             |  Smaller tiles require less resources but may increase the running time. If a tile cuts a flooded area, water level/depth estimates can be inaccurate along the border. Larger tiles reduce this problem but the size has to account for computational resources                                                                                                                                                         																            |
|`param_merge_tiles`                  |   True            | True, False                |  -      | If `True`, the tiled outputs are automatically merged                                                                                                                                                        |                                                                                                                                                                                                                                                                                                                                                                                                                         																		    |
|`param_output_map`                   |   'WL_WD'         | 'WL_WD', 'WL', 'WD'        |  -      | Specifies what outputs should be generated (only Water Level, only Water Depth, both)                                                                                                                        |  Water level is in the vertical units of the DTM (e.g. m a.s.l). Water depth is in cm. If a permanent water body layer is given as input, WL and WD will be displayed with a fictitious value of 9999 therein                                                                                                                                                                                                           																		    |
|`param_WL_estimation_method`         |   'method_A'      | 'method_A', 'method_B'     |  -      | Selects the method used to estimate water level inside flooded areas                                                                                                                                         |  Method_A: uses the inverse distance weighted elevation of the pixels along the border of the flooded area; Method_B: uses `param_border_quantile` as inverse distance weighted quantile in the distribution of the pixels elevation along the border                                                                                                                                                                     																		|
|`param_threshold_slope`              |   0.1             | [0, 1]                     |  -      | Pixels along the borders of flooded areas with slopes larger than this are not used as a reference for estimating water levels                                                                               |  The value is a tradeoff depending  on the accuracy and resolution of the input rasters (especially the flood delineation and DTM). Lower values exclude more pixels (potentially increasing the accuracy but with the risk of losing information). Higher values allow steeper pixels along the border to contribute to the water level estimates (but it can introduce errors when the input rasters are not accurate or in case of coarse resolution). 										|
|`param_size_gaps_close`              |   0.01            | [0, 1]                     |  $km^2$ | Holes in the initial flood map larger than this are filled                                                                                                                                                   |  Especially in automatically-derived flood maps, small holes are often errors and/or feature inaccurate wet-dry borders. Thus, holes can have a negative effect in the water level estimation. Removing them usually improves the results. However, large `param_size_gaps_close` can cause the loss of precious wet-dry borders.                                                                                    																			    |
|`param_max_number_neighbors`         |   200             | [1, 1000]                  |  -      | Maximum number of pixels along the border that are used to estimate the water level in each flooded pixel                                                                                                    |  Considering more pixels along the border improves robustness but increase computational burden. Large values (especially when the resolution of the input rasters and/or `param_distance_range` are low) might result in distant unrepresentative border elevations to concur for the estimation of water level.                                                                                                       																		    |
|`param_inverse_dist_exp`             |   1               | [0, 5]                     |  -      | Inverse distance weighting exponent used to estimate the water level inside flooded areas based on the ground elevation along the flooded borders                                                            |  Water level estimates will be mostly controlled by the elevation of nearby borders when the inverse distant exponent is high. For lower values of the exponent, futrher points along the border will contribute to the water level estimation making the result smoother. The value should be a tradeoff balancing a realistic (flat) water surface which at the same time follows the actual water level variability. 																		    |
|`param_border_subsampling`           |   0               | [0, 1000]                  |  -      | Parameter modulating the relationship between the size of a flooded area and the share of pixels along the flood borders used to estimate water level. 0: uses all valid border pixels ; larger values sample just a fraction of them          |  Larger values might be necessary for inaccurate inputs (especially flood delineations), particularly for high resolutions. This is because if flood delineation is locally wrong (especially in steep terrains), border pixels might  not represent the elevation of the actual flood border  ( causing a biased water level estimation). Larger values of `param_subsampling` ensure the use of further border pixels, possibly increasing the robustness of the water level estimation         |
|`param_min_flood_border_size`        |   10              | [1,1000]                   |  -      | If the number of valid pixels along the border is less than this, WL is estimated using the `param_inner_quantile` quantile of the distribution of the elevation of the pixels inside the flooded area       |  When water level in a flooded area is estimated using the `param_inner_quantile` of the ground elevation inside the flooded area, the resulting water level will be flat for the entire contiguous flooded area. As a consequence, the flooded areas for which water levels are estimated with this method should not feature significant slopes in the water surface                                                   																		    |
|`param_border_quantile`              |   0.5             | [0, 1]                     |  -      | It is the quantile in the distribution of the ground elevation in correspondence of the flood border which is used as a reference to estimate water level (relevant if "method_B" is selected)               |  Tuning the quantile can be useful to compensate for biased flood extent or to generate different scenari. Method_B can produce less smooth results but can be more robust against errors in the flood delineation and/or in the DTM                                                                                                                                                                                 																			    |
|`param_inner_quantile`               |   0.98            | [0, 1]                     |  -      | For  flooded areas with less border pixels than `param_min_flood_border_size`, FLEXTH uses the `param_inner_quantile` of the elevation of the pixels inside the flooded area to estimate water levels        |  Ideally, the water level in a flooded area should approach the maximum ground elevation among the flooded pixels. Given the errors in the flood delineation and/or in the DTM it is better to use an upper quantile                                                                                                                                                                                                                                                                              |
|`param_spread_outside_exclusion_mask`|   True            | True/False                 |  -      | If `True`, flood propagation is allowed even outside the exclusion mask (i.e. outside no-data areas)                                                                                                         |  If the confidence is low in not having flood water in areas marked as unflooded, the flood propagation also outside the no-data areas can be activated. In this way water will be propagated from flooded areas as long as the ground topography allows                                                                                                                                                                                                                                          |
|`param_max_propagation_distance`     |   10              | [0, 100]                   |  $km$   | Parameter controlling how the initial size of a flooded area modulates the maximum distance at which flood water can spread away from the initial flood border                                               |  Larger values allows propagation to extend further (provided ground topography permits). Settings very large values migh increase the risk of excessive and unrealistic flood propagation. This can occur in case of erroneous water level estimates caused by inaccurate flood delineations and/or DTM and/or coarse resolutions. Particular care should be places if `param_spread_outside_exclusion_mask = True` as flood propagation is less constrained                            		    |
|`param_distance_range`               |   10              | [0, 100]                   |  $km^2$ | Flooded areas of this size ($km^2$) reach half of the maximum propagation distance `param_max_propagation_distance`                                                                                          |  Parameter controlling the rate at which the maximum propagation distance `param_max_propagation_distance` is approached as the size of the flooded area increases                                                                                                                                                                                                                                                       																		    |
|`param_WD_star`                      |   10              | [0, 100]                   |  $cm$   | Dummy water depth assigned to those pixels in the initial flood delineation where the estimated water depth is below ground surface (i.e. $WL<DTM$)                                                          |  When estimating water levels based on ground elevation along flood borders, it can occur that the estimated water levels lie below the ground elevation at pixels that are supposed to be flooded. This can result from errors in the DTM, inaccuracies in flood delineation, or strong curvatures in the water surface (e.g., due to hydrodynamic effects). Assuming that these pixels are actually flooded requires a fictitious water depth to be assigned therein                            |

For additional details: Betterle and Salamon (2024) - https://nhess.copernicus.org/articles/24/2817/2024/


# Note
Water level can visually be used to evaluate the results. Depending on the resolution and on the quality of the
 input DTM and flood delineation, the parameters of FELXTH can be tuned in order to obtain smoother results. In general, smoother water surfaces are obtained:
1. increasing `param_max_number_neighbors` and/or
2. decreasing `param_inverse_dist_exp`  and/or
3. increasing `param_border_subsampling` and/or
4. using 'method_A' as `param_WL_estimation_method` and/or
